# PingCRM Google implementation contract

Branch: `codex/google-contacts-enrichment`. Changes are tested with synthetic data; production rollout is separate. Background research is in [google-contacts-enrichment.md](google-contacts-enrichment.md).

## Shared model 
GoogleContactLink table: id UUID, contact_id UUID FK cascade, google_account_id UUID FK cascade, resource_name String, etag String nullable (CONTACT source etag), snapshot JSONB dict full Google person needed fields, labels JSONB list of {resource_name,name}, last_imported_at datetime; unique(google_account_id,resource_name). Contact ownership derives contact.user_id and google_account.user_id; always validate both. One CRM contact may have several links. Export imports from app.models.google_contact_link.GoogleContactLink.
GoogleAccount.granted_scopes nullable JSON/JSONB list[str] (export model, import migration). Legacy links require verified account: no guessing on multi-account legacy resource_name. Preserve legacy google_resource_name during transition; never archive contacts based on partial/failed/empty account import. Merge migrates links and birthday/avatar/user_edited_fields.

## API contract 
GET /api/v1/contacts/{contact_id}/google -> Envelope data {gmail_enabled:boolean, links:[{id:string,account_email:string,resource_name:string,labels:[{resource_name:string,name:string}],google_url:string|null,can_write:boolean}], details:[{link_id:string, birthdays:any[], biographies:any[], addresses:any[], urls:any[], userDefined:any[]}]}. Use actual typed schemas instead of any in implementation; raw Google values may use dict[str,Any] only server snapshot DTO. google_url only if identifier conversion verified or explicit supported contact source mapping; otherwise null with UI fallback search in Google, not guessed ID. Existing scalar fields imported normally.
POST /api/v1/contacts/{contact_id}/google/preview body {link_id:string} -> Envelope data {preview_id:string,account_email:string,expires_at:string,changes:[{field:string,label:string,current:unknown,proposed:unknown,selected_by_default:boolean}],can_write:boolean}. Prefer selected fields enum names emails,phones,full_name,company,title,birthday,urls. Exclude notes/tags/relationship/messages by default. No automatic deletion or creation. Actual Google latest read required. Merge list groups preserving metadata/labels/unselected data. Names/birthday/company existing replacements unchecked by default.
POST /api/v1/contacts/{contact_id}/google/apply body {preview_id:string,fields:string[]} -> Envelope data {status:string,updated_fields:string[]}. Bind previews in Redis to user/contact/link/CRM version/source etag, TTL e.g.10min; serialize per GoogleAccount with lock, prevent concurrent/replayed apply, retain outcome; version conflict409 requires new preview, timeout outcome unknown requires re-read, not blind retry. Audit only owner/contact/account IDs, selected field names and outcome in infrastructure logs; do not log contact values or tokens. Persistent before/after audit storage is deferred. Snapshot full source metadata mandatory for Google PATCH. No writes in preview.
GET /api/v1/contacts/google-labels -> Envelope data [{id:string,name:string,account_email:string}] . Filter contacts listing parameter google_label (resource_name or id stable account qualified); frontend may show label filter with server query, not filter only current page.
OAuth GET /api/v1/auth/google/url?write_contacts=true for additional contacts write consent; default read contacts +calendar+identity no Gmail. Connect flow retains current CRM user even Google email differs. Save actual granted scopes, reject missing required grants clearly. Gmail feature disabled by default via GOOGLE_GMAIL_ENABLED false; disabled endpoints/jobs do not access Gmail. UI sync only contacts/calendar. Keep calendar read-only.

## Acceptance
Full richer import birthday with/without year, names primary precedence respecting user edits, labels exact case separate from tags; repeated import no duplicates, account/source provenance, no mass archival. Organizations created/linked from company and repeat-safe backfill with preview/dry run protecting manual links. Manual export preview selected additive changes, never data loss, ownership, etag+CRM conflicts, idempotence, errors, no Gmail. Tests must cross real code seams and PostgreSQL persistence where relevant. No implementation-copy tests. No production assertions without executed checks.
